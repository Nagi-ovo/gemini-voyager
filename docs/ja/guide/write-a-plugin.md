# 自分でプラグインを作る

ローカルプラグインは、自分のために作るプラグインです。Gemini、AI Studio、ChatGPT、Claude、DeepSeek の見た目やレイアウトを変えられ、保存先は自分のブラウザの中だけ。PR を出す必要も、Voyager のソースコードを手元に用意する必要もありません。

ほかの Voyager プラグインと同じく宣言的で、`plugin.json` マニフェストと CSS だけでできています。プラグイン自身がコードを実行することはありません。Voyager がインポート時に内容をチェックして変更を適用し、オフにすればすべての変更を元に戻します。インポートしたプラグインは最初オフになっているので、中身を確かめてから有効にできます。

## 3 つの作り方

### やりたいことを書いて、好きな AI に書かせる

1. 変えたいサイトを開き、Voyager の popup で「ローカルプラグイン」カードを探します（Gemini と AI Studio では設定のいちばん最後にあります）。
2. 「ひとことで画面を変える」を選び、やりたいことを一文で書いて（例：「自分のメッセージの幅を狭くして、サイドバーを隠す」）、「プロンプトを作成」を選びます。
3. プロンプトを自分で好きな AI チャットにコピーし、返ってきた回答を丸ごと貼り戻して「回答をチェック」を選びます。
4. そのプラグインで何が変わるのかを、Voyager がわかりやすい言葉で説明します。インポートしたら、プラグイン一覧でオンにしてください。

Voyager がプロンプトをどこかへ送ることはありません。使う AI を選ぶのも、テキストを行き来させるのもあなた自身です。

### コーディングエージェントに任せる

コーディングエージェント（Claude Code、Codex、Cursor など）を使っているなら、Voyager のプラグイン skill を渡してください。

```text
https://voyager.nagi.fun/skills/write-voyager-plugin/SKILL.md
```

「ローカルプラグイン」カードで「ひとことで画面を変える」を開くと、このリンクをコピーする「skill のリンクをコピー」ボタンがあります。skill には、マニフェストのフィールド、各サイトが宣言している内容、プリミティブ、プラグインにできないことまで、仕様がひととおり入っています。ほしい変更をエージェントに伝えれば、フォルダを用意して `plugin.json` と `style.css` を書き、オフラインでチェックまで済ませてくれます。あとは popup で「ファイルをインポート」を選び、2 つのファイルを指定するだけです。

skill をいつでも使えるようにしておくなら、エージェントの skills フォルダに `write-voyager-plugin/SKILL.md` として保存します（Claude Code なら `~/.claude/skills/`）。

### 手で書く

Node.js 18 以降が必要です。

```sh
npx create-voyager-plugin@latest init my-plugin --site claude
# my-plugin/plugin.json と my-plugin/style.css を編集
npx create-voyager-plugin@latest check my-plugin
```

`init` は、そのままでチェックを通る `plugin.json` と `style.css` に加えて、そのサイトのルールをまとめた `AGENTS.md` を書き出します。`--site` には `gemini`、`aistudio`、`chatgpt`、`claude`、`deepseek` のいずれかを指定します。

`check` は popup でのインポートと同じチェックをオフラインで実行します。インポートできる状態なら終了コード 0 を返し、そうでなければ問題ごとに `path: message` 形式の行を 1 行ずつ出力します。`--json` を付けると機械可読な形式で出力します。

## プラグインにできること

- CSS を追加する。適用範囲は、プラグインがページに付ける `gv-` クラスの下に限られます。
- クラスの追加、安全な属性やインラインスタイルの設定、要素の非表示。対象には、サイトが宣言しているセマンティックキー（`userTurn`、`assistantTurn`、`composer` など）か CSS セレクタを指定します。
- popup に設定項目（スイッチ、スライダー、ドロップダウン）を用意する。設定値は `{{key}}` トークンで CSS に渡されます。
- ChatGPT、Claude、DeepSeek では、Voyager のプリミティブ（数式コピー、タイムライン、Mermaid 図など）を有効にしたり、Voyager 自身の UI の色を変えたりできます。

## プラグインにできないこと

JavaScript の実行、クリックやキー入力への反応、ネットワークからの読み込み（フォント、画像、スタイルシート）、メッセージ内容の読み取りや書き換え、ほかのサイトでの動作はできません。依頼にそうした要素が含まれている場合、作成用の資料は AI にそのことを正直に伝えさせ、実現できるいちばん近い形で作らせます。

## インポート時にチェックされるルール

共通のマニフェストチェック（[プラグイン貢献ガイド](./plugin-contribution.md)を参照）に加えて、ローカルプラグインは次の条件を満たす必要があります。

- Voyager が対応しているサイトの範囲内の URL にだけマッチすること
- マッチするすべてのサイトが宣言しているセマンティックキーだけを使うこと
- `addClass` 1 つにつきクラスは 1 つだけで、`gv-` で始まること
- 設定は boolean、number、select のいずれかであること（string と color にはまだ popup の UI がありません）
- Gemini と AI Studio では `theme` を使わず、プリミティブは各サイトが許可するものだけを使うこと: Gemini では `formulaCopy`、`vimInput`、`userLatex`、`codeCollapse`、`mermaid`、`wavedrom`、`echarts`、AI Studio では `formulaCopy`。いずれも Voyager 標準の対応する設定と同じコードを実行する。`formulaCopy` と `vimInput`(数式コピー・入力欄 Vim モード)は、同じページで標準設定とプラグインのどちらか一方だけが動く。ページの読み込み時や、どちらも動いていないときは標準設定が優先され、その後はすでに動いている側がそのまま動き続け、もう一方は一時停止と表示される。どちらかをオフにすると、もう一方が引き継ぐ。それ以外は要素ごとに担当を取り合うため、標準設定と同時に動かせる: 相手がすでに処理している行やコードブロックには手を出さない

翻訳（`i18n`）は任意です。

## 共有する

ローカルプラグインは自分のブラウザの中にしかありません。別の環境へ移すときは、プラグイン一覧から JSON をエクスポートしてください。みんなの役に立ちそうなら、公式カタログへの収録を提案することもできます。その流れは[プラグイン貢献ガイド](./plugin-contribution.md)で説明しています。

送信ショートカットのプラグインはページごとに1つだけ実行できます。後から有効にしたものには競合が表示されます。任意の `mode`（sinceEngine `next`）は `ctrlEnterSends`（既定）または `enterSends` です。IME の確定キーでは送信しません。Gemini/AI Studio では機能の移行後に利用できます。
