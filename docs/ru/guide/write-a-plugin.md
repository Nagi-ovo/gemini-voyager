# Создание своего плагина

Локальный плагин вы делаете для себя. Он меняет внешний вид или раскладку Gemini, AI Studio, ChatGPT, Claude или DeepSeek, хранится только в вашем браузере и не требует ни pull request, ни исходного кода Voyager.

Как и любой плагин Voyager, он декларативный: манифест `plugin.json` плюс CSS. Собственного кода он не выполняет. Voyager проверяет плагин при импорте, применяет его изменения и полностью убирает их, когда вы его выключаете. Импортированный плагин сначала выключен, так что его можно спокойно просмотреть.

## Три способа сделать плагин

### Опишите изменение, а код напишет любой ИИ

1. Откройте сайт, который хотите изменить, откройте popup Voyager и найдите карточку **Локальные плагины** (в Gemini и AI Studio это последний пункт настроек).
2. Выберите **Описать изменение**, напишите одно предложение («Сделай мои сообщения уже и скрой боковую панель») и выберите **Составить промпт**.
3. Сами скопируйте промпт в любой чат с ИИ, вставьте обратно его ответ целиком и выберите **Проверить ответ**.
4. Voyager простыми словами покажет, что меняет плагин. Импортируйте его, а затем включите в списке плагинов.

Voyager никуда не отправляет промпт: вы сами выбираете ИИ и сами переносите текст туда и обратно.

### Поручите это ИИ-агенту для кода

Если вы пользуетесь агентом для программирования (Claude Code, Codex, Cursor и подобными), дайте ему skill Voyager для плагинов:

```text
https://voyager.nagi.fun/skills/write-voyager-plugin/SKILL.md
```

В карточке **Локальные плагины** откройте **Описать изменение** — там есть кнопка **Копировать ссылку на skill**. В skill описан весь контракт: поля манифеста, что объявляет каждый сайт, примитивы и то, чего плагин сделать не может. Попросите агента о нужном изменении: он создаст папку, напишет `plugin.json` и `style.css` и проверит их офлайн. Затем выберите **Импорт файлов** в popup и укажите оба файла.

Чтобы skill всегда был под рукой, сохраните файл как `write-voyager-plugin/SKILL.md` в папке skills вашего агента (для Claude Code это `~/.claude/skills/`).

### Напишите вручную

Нужен Node.js 18 или новее:

```sh
npx create-voyager-plugin@latest init my-plugin --site claude
# отредактируйте my-plugin/plugin.json и my-plugin/style.css
npx create-voyager-plugin@latest check my-plugin
```

`init` создаёт `plugin.json` и `style.css`, которые уже проходят проверку, а также `AGENTS.md` с правилами для выбранного сайта. `--site` принимает `gemini`, `aistudio`, `chatgpt`, `claude` или `deepseek`.

`check` офлайн выполняет те же проверки, что и импорт в popup. Если плагин импортируется, команда завершается с кодом 0, иначе выводит по одной строке `path: message` на каждую проблему. Добавьте `--json`, чтобы получить машиночитаемый вывод.

## Что умеет плагин

- Добавлять CSS, ограниченный классом `gv-`, который плагин ставит на страницу.
- Добавлять класс, задавать безопасный атрибут или inline-стиль, скрывать элементы. Цели — семантические ключи, которые объявляет сайт (`userTurn`, `assistantTurn`, `composer` и т. д.), или CSS-селекторы.
- Показывать настройки в popup: переключатели, ползунки и выпадающие списки; их значения попадают в CSS через токены `{{key}}`.
- В ChatGPT, Claude и DeepSeek включать примитивы Voyager (копирование формул, таймлайн, диаграммы Mermaid и другие) и перекрашивать собственный интерфейс Voyager.

## Чего плагин не умеет

Плагин не может выполнять JavaScript, реагировать на клики или нажатия клавиш, загружать что-либо из сети (шрифты, изображения, таблицы стилей), читать или переписывать текст сообщений и работать на других сайтах. Если запрос требует чего-то из этого, материалы для авторов велят ИИ прямо об этом сказать и собрать самый близкий вариант, который реально работает.

## Что проверяется при импорте

Помимо общих проверок манифеста (см. [Участие в плагинах](./plugin-contribution.md)), локальный плагин должен:

- совпадать только с URL внутри сайтов, которые поддерживает Voyager;
- использовать только те семантические ключи, которые объявлены на всех совпадающих сайтах;
- добавлять ровно один класс на каждый `addClass`, и этот класс должен начинаться с `gv-`;
- использовать только настройки типа boolean, number или select (у string и color пока нет элемента управления в popup);
- не использовать `theme` в Gemini и AI Studio, а из примитивов брать только те, что разрешает каждый сайт: `formulaCopy`, `vimInput`, `userLatex`, `codeCollapse`, `mermaid`, `wavedrom` и `echarts` в Gemini, `formulaCopy` в AI Studio. Они запускают тот же код, что и встроенные настройки Voyager. `formulaCopy` и `vimInput` (копирование формул и режим Vim в поле ввода) работают на странице в одном экземпляре: либо встроенная настройка, либо плагин, но не оба. При загрузке страницы или пока ни один из них не работает, приоритет у встроенной настройки; дальше тот, что уже работает, продолжает работать, а другой показывается приостановленным. Выключите один из них, чтобы работу взял на себя другой. Остальные занимают элементы страницы по одному и работают одновременно со встроенной настройкой: строку или блок кода, который уже занял другой, они оставляют ему.

Переводы (`i18n`) необязательны.

## Как поделиться

Локальный плагин остаётся в вашем браузере; чтобы перенести его в другое место, экспортируйте его JSON из списка плагинов. Если он пригодится всем, предложите его в официальный каталог: этот путь описан в разделе [Участие в плагинах](./plugin-contribution.md).

На странице работает только один плагин сочетания клавиш отправки; следующий показывает конфликт. Необязательный `mode` (sinceEngine `next`) — `ctrlEnterSends` (по умолчанию) или `enterSends`. Подтверждение ввода IME не отправляет сообщение. Gemini/AI Studio открывают примитив после переноса функции.
